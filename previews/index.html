Six findings

The part that changes what you should build.

1

Nobody ships an animation library for this

Not one of the six sites above loads GSAP, Lenis, or Framer Motion. The heaviest motion site, Bruno Simon, is a single WebGL bundle, not a CSS toolkit. The sites that feel best (emilkowal.ski, antfu.me) use seven and two keyframes respectively. You do not need a dependency. You need better timing.

2

Even Resend uses almost no scroll-linked animation

I scrolled Resend through five positions and read every running animation. It had 46 animations running and zero of them were on a ScrollTimeline or ViewTimeline — all 46 ran on the normal document clock. Sites reveal on scroll with an IntersectionObserver adding a class, then the animation plays once in real time. Scroll-linked CSS is for the accent, not the backbone.

3

Scroll-driven CSS is finally safe to use

animation-timeline: view() and scroll() ship in Chrome 115+, Edge 115+, Firefox 132+, and Safari/iOS 18+ — roughly 84% of traffic as of mid-2026. The two rules that break it: declare animation-timeline after any animation shorthand (the shorthand silently resets it to auto), and set animation-duration: 1ms or Firefox ignores the effect entirely.

4

Tokens beat hand-tuned values

Your styles.css has 0.2s ease hardcoded in about twelve places and two different border/background pairs. The single highest-leverage change is not an animation at all — it is declaring five duration tokens and four easing tokens in :root and pointing everything at them. That is what makes motion feel deliberate rather than assembled.

5

Small amplitude reads as expensive

20px is the slide distance everyone ships, which is exactly why it reads as a template. 8–12px is the refined range. Same for hover scale: keep it at or below 1.02 for buttons, 1.02–1.05 for cards. Also: entrances ease out, exits ease in and run at about 75% of the entrance duration, stagger sits between 30 and 80ms, and linear is only correct for marquees and scroll-linked progress.

6

Restraint is the differentiator now

The current taste consensus is that over-animating is the failure mode, not under-animating. The widely-repeated budget: a hero gets at most three staggered entrances and one scroll-linked element. Scroll-jacking, body parallax, and a spring on every hover are all listed as things to avoid. Your restrained editorial direction is already the harder half of the problem.

One real bug to fix before you add any scroll-driven animation

Your existing reduced-motion block in styles.css:746 only forces durations to near zero. I tested that exact block against a scroll-driven animation with reduced motion emulated on: the element kept moving, travelling from 0 to 245px to 545px down the page. Scroll-driven animations ignore animation-duration entirely, because the scroll position is the clock — so your current block would silently fail to stop them for users who asked for less motion.

The fix is one extra line per scroll-driven system. This is already in previews/motion.css:

@media (prefers-reduced-motion: reduce) {
  .scroll-rail,
  .timeline-draw,
  .project-thumb {
    animation: none !important;
    /* required — the duration reset below cannot catch these */
    animation-timeline: none !important;
    transform: none !important;
  }
}

Ranked for your specific site

Ordered by value against effort, for a recruiter-facing portfolio that must load instantly and work on a phone. Each is toggleable on the live preview.

1

Motion tokens in :root

Five durations, four easings, three stagger intervals. Replaces the scattered 0.2s ease values. Invisible on its own, but every other effect inherits its consistency from here.

~20 lines CSS · no JS · do this first
2

Staggered scroll reveal

Fade plus 12px rise as each section enters, 55–70ms between siblings, plays once. The single biggest perceived-quality jump. One IntersectionObserver, and it degrades to fully visible content if the script never runs.

~25 lines JS + CSS · biggest payoff
3

Hero name mask reveal

Your name rises out from behind a clip, one word per line, 90ms apart. It makes the hero read as one composed opening alongside the typewriter you already have rather than two disconnected tricks.

~15 lines JS + ~20 lines CSS
4

Scroll progress rail

A 2px accent line on the left edge filling as you scroll. The one scroll effect that costs zero JavaScript, and it pairs with the sticky section rail you already have. This is your one scroll-linked element.

~10 lines CSS · needs the reduced-motion fix
5

Timeline line draw

Your experience section's vertical line paints downward as the card arrives. Communicates sequence, which is the one thing motion in that section should actually do.

~12 lines CSS · one markup change
6

Card cursor spotlight

A soft accent glow following the pointer across project and contact cards. Gives the flat hairline cards some life without reintroducing the drop shadows the design avoids. Gate on @media (hover: hover) so it does not stick lit on touch.

~20 lines JS + ~15 lines CSS · optional
7

Thumbnail settle on scroll

Screenshots scale from 1.05 to 1.0 as a card passes. Nice, but it is a second and third scroll-linked element, which starts to work against the one-per-viewport budget. Take it or leave it.

~15 lines CSS · cut on mobile

What I would not add

  • Scramble / decode typewriter. The most recognisable AI-portfolio tell there is. Your existing typewriter already does the job and reads as more restrained. Keep yours.
  • Infinite tech marquee. With four small skill groups and one timeline entry it reads as padding. Reconsider only if the skill list passes twenty items.
  • Conic gradient spin border. A 2024–2025 staple that is now thoroughly expected, impossible to do tastefully at hairline weight on near-black, and it would put a second permanent loop next to your blinking caret.
  • Magnetic buttons and cursor followers. Playful rather than professional, and they fight the scroll rail for the same attention.
  • Count-up number stats. You have two years of experience and one role. A counter animating up to 2 undersells it.
  • Body parallax. Actively harms scroll performance and is hostile to reduced-motion users.
